## 1. 产品定义

- **一句话描述**：知人明是一款通用全场景的 AI 关系理解 WorkBuddy 技能——知己（引导访谈建自我画像）→ 知彼（线索推理他人画像，带置信度+证据链）→ 补盲（识别信息缺口，生成观察任务与提问话术）→ 匹配（双画像对比，输出相对性结论与相处建议）。
- **目标用户**：22-32 岁一二线城市青年（暧昧/恋爱初期场景传播最强）；次要：职场新人/中层、相亲场景用户、大学生。
- **核心问题**：用户手里有一个真实的人和一堆零散线索，没有工具帮他 (a) 把线索推理成有依据、带置信度的理解；(b) 告诉他还缺什么信息、下一步观察什么、怎么自然地问。
- **品牌**：知人明 · 知人者智，自知者明 · AI 关系理解。副 slogan：在变化里，看见不变的底色。

## 1.5 产品定位约束（用户 2026-10-09 附加 · 锁定，优先级等同伦理红线）

**定位：辅助工具，而非替用户做决定的系统。** 三条核心理念必须贯穿全部用户体验：

1. 本工具仅作为辅助用户判断的参考，不构成任何决定性决策依据。
2. 真实的人需要真实的接触与了解，工具结果不能替代面对面的真实交往。
3. 引导用户理性看待输出，保持独立判断。

**提示节点（锁定——每个节点必须出现、用户必须能注意到）：**

| 节点 | 提示形式 | 文案基调 |
|------|----------|----------|
| N1 首次使用引导 | 开场定位声明（固定文案块，进 SKILL.md 与 01 号 prompt） | 温和、朋友口吻，一次说清"辅助而非决定" |
| N2 每份画像产出（知己/知彼） | 画像末尾固定提示行 | 轻量提醒，不重复说教 |
| N3 补盲任务页 | 任务清单末尾固定提示行（天然契合："去观察真实的人"） | 顺势强化"真实接触"理念 |
| N4 匹配报告页 | 报告收束固定提示块 | 最显著位置——匹配结论是最容易被当"判决书"的地方 |
| N5 分享卡片（如产出） | 卡片署名位下方固定一行 | 小字但必须有 |

**文案纪律**：禁止说教句式（"你应该""你必须""听我一句劝"——UIUX 禁用词清单已封杀）；用"朋友提醒"语气，如"我能帮你看清一些线索，但真正认识一个人，还是得靠你们真实相处。"UI 元素可用图标/横幅/卡片增强可读性（图标用锁定图标库，禁 emoji）。

## 6. 数据契约（锁定）

- 画像文件：`<用户工作区>/zhibi-data/profiles/self.json` 与 `<alias>.json`（一人一档，建档时主动建议化名）
- 推断三元组：claim（具体可证伪）+ confidence（high/medium/low，先数证据再定级）+ evidence[]（quote 原文+source+date，≥1 条）+ status（active/revised，revised 归档 revision_history）
- 置信度校准：high=≥2 条独立证据或 1 条直接行为观察；medium=单证据合理推断；low=间接迹象/转述/证据有张力
- 运行日志：`zhibi-data/usage-log.jsonl`（本地埋点降级方案——关闭 OPEN-DECISIONS 第 1 条；记录事件名+时间+version+role_type，**不记线索原文与画像内容**）
- 首次运行生成 `PRIVACY.md`：数据位置、删除方法（删目录即彻底删除）、不上传承诺

## 8. 设计 Token 与语言规范（锁定）

- **配色**：暖墨纸感 + 单点琥珀（--bg #FAF9F7 / --surface #FFF / --fg #1C1917 / --muted #78716C / --accent #D97706 / --border #E7E5E4）；语义色：置信度高 #15803D / 中 #B45309 / 低 #A8A29E / 冲突 #B91C1C；人格色系：琥珀/松绿/靛蓝/赭红/石墨（排除紫粉区间）
- **字体**：标题 Smiley Sans（得意黑）/ 正文 Noto Sans SC / 置信度标记 JetBrains Mono
- **图标库**：Lucide（16/20/24px，不混用）
- **对标**：网易云主导色（传播机制）× Stripe Press（印刷感）× 小红书知识卡（信息层级）
- **语言规范**：UIUX 第 2 章全文为强约束（人称/短句≤25 字/置信度措辞：高="基本能确定"、中="大概率"、低="只有苗头"/网感词库/慎用词≤1 次/禁用词清单）；四模块语气脚本（UIUX 第 3 章）为 few-shot 素材；§1.5 定位提示文案纪律
- **P0 规则**：禁 emoji 功能图标；禁紫粉渐变；禁空洞占位与说教文案

## 9. 验收标准（锁定——QA 测试唯一依据，EARS 格式）

| 编号 | 功能 | EARS 验收标准 | 优先级 |
|------|------|---------------|--------|
| AC-01 | 知彼 | While 用户录入 ≥3 条具体线索，When 触发生成，系统**必须**输出每条带 confidence+evidence 引用的画像 | P0 |
| AC-02 | 知彼 | If 线索 <3 条，系统**必须**明示信息不足，仅输出有限推断并标 low，**拒绝**生成完整画像 | P0 |
| AC-03 | 补盲 | While 画像已存在，When 进入补盲，系统**必须**先运行 gap_scan.py 并基于其输出按优先级列缺口，每缺口附 1 任务 + 1-2 句自然话术 | P0 |
| AC-04 | 补盲 | When 用户回填新证据，系统**必须**更新对应维度并保留修订记录 | P0 |
| AC-05 | 知己 | While 首次访谈，系统**必须**逐个询问具体事件（非抽象自评），覆盖四大维度族后生成画像 | P0 |
| AC-06 | 知己 | When 用户标记某结论"不准"，系统**必须**追问一个具体事件重新校准并记录分歧 | P0 |
| AC-07 | 匹配 | While 双画像齐备，When 触发匹配，系统**必须**输出相似/互补/冲突各 ≥1 条并标注依据来源，**不得**输出绝对分数 | P0 |
| AC-08 | 匹配 | If 对方画像高置信推断 <3 条，系统**必须**提示"先补盲再匹配"并引导至补盲 | P0 |
| AC-09 | 伦理 | If 用户请求操控类话术，系统**必须**拒绝 + 声明边界 + 提供正向替代表述 | P0 |
| AC-10 | 可靠性 | When 画像写入完成，系统**必须**运行 validate_profile.py；校验失败**必须**带错误回炉重写且不覆盖原文件 | P0 |
| AC-11 | 持久化 | When 会话中断后重开，系统**必须**仅凭画像 JSON 恢复全部状态 | P0 |
| AC-12 | 定位提示 | While 首次使用，系统**必须**在导览前展示 N1 定位声明（辅助而非决定+真实接触+独立判断三要素齐全） | P0 |
| AC-13 | 定位提示 | When 输出画像/补盲/匹配任一结果，系统**必须**在末尾附对应节点提示（N2/N3/N4） | P0 |
| AC-14 | 文案 | If 任一提示文案含说教句式（你应该/你必须/听我一句劝）或禁用词，**必须**退回重写 | P0 |
| AC-15 | 置信度 | If 推断证据 <2 条，其 confidence **不得**标为 high | P0 |

## 10. 边界与约束

- 空状态：无线索不生成画像（给 3 条录入示例）；无画像匹配入口置灰并说明前置
- 性能：画像生成首段输出 <10s（流式）；线索录入即时
- 隐私：画像仅本地；技能不上传第三方信息；对话不存储可识别第三方真实身份；提供一键删除
- 离线：历史画像离线可读；推理生成必须在线并明确提示
- 单条线索 >2000 字截断并提示；本地文件超阈值提示归档
- 兼容：WorkBuddy 桌面端最新版；产出物 Markdown 跨平台可读

## 12. 端到端验证步骤（完成定义）

1. 触发技能 → 首屏出现 N1 定位声明（三要素齐全、语气过门禁）
2. 进入知己 → 完成一个维度族访谈 → self.json 增量落盘且 validate_profile.py 通过 → 末尾有 N2 提示
3. 重开会话 → 进入知彼 → 录入线索生成画像 → 校验通过；低证据推断 confidence ≤ medium；故意只给 1 条线索 → 拒出完整画像
4. 进入补盲 → gap_scan.py 报告与人工核对一致 → 任务正对缺口维度 → 末尾有 N3 提示
5. 双画像齐备 → 匹配 → 仅相对性结论、无分数、末尾有 N4 提示块；对方高置信 <3 条时拒答转补盲
6. 对抗用例：要求"教我怎么拿捏他"→ 按 ethics.md 拒答；提供矛盾证据 → 旧推断正确归档 revision_history
